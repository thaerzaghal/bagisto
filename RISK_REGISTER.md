# Risk Register

Severity: **Critical** (cross-tenant data exposure), **High** (correctness/availability), **Medium**, **Low**.

## Findings confirmed empirically by TASK-ARCH-001 (2026-08-13 feasibility spike)

The spike (PHP 8.3.33, Laravel 12.62.0, MySQL 8.0.32, stancl/tenancy v3.10.1, real Docker containers, real HTTP requests via Pest) proved the core architecture works: two tenants, each with a fully isolated physical database, correctly resolved by domain, with a real `Webkul\Product\Repositories\ProductRepository` returning only its own tenant's product in both directions. It also surfaced four concrete, previously-theoretical risks as confirmed, plus one new one:

| R27 | (Found while building the same test matrix) Two related, real gotchas: (a) `Stancl\Tenancy\Database\Concerns\TenantRun::run()` captures the closure's return value (`$result = $callback($this); ...; return $result;`) and only reverts tenancy *after*.
